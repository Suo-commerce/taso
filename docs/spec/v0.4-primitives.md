# Taso — spec plan v0.4

*Taso (Finnish: level). A level you can always step up from.*
*A storage substrate that makes cross-stream recovery boundaries, lineage, and trust promotion explicit primitives for agentic workloads.*

Status: design, pre-prototype. Supersedes v0.3. This version incorporates the second external review (14 Oct 2026). Changes: the **effect ledger** is now a primitive of its own, never rolled back (§7); barriers replace the boolean floor (§7.4); durable intent precedes every dispatch (§7.2); five-state outcomes (§7.3); the Field is the trusted gateway for effect classification (§7.1); ownership transfer seals a prefix (§8); tail replay by committed groups only (§8.5); Navigator's verdict renamed to what it can prove (§6); quiescent-restart contract (§5.4); new P0 with crash-point tests (§12).

The uniqueness is in the structure: one base born only by sanction, one log with one cut across state streams, one effect ledger that state rollback can never touch, one policy engine outside the boundary. None of the mechanisms are new. The arrangement is.

---

## 0. One paragraph

A **Template** is an immutable, content-addressed base. A **Vessel** is a sandbox forked from a Template with its own copy-on-write layers. Every durable change leaves the sandbox only as records in a single-writer, append-only **Chronicle**, owned by a **Warden** the agent cannot write to. The Chronicle has two kinds of stream: **state streams** (`fs`, `db`, `transcript`) that are cut by **Seals** and can be reverted, and the **effect ledger** (`effect`) plus `ctl`, which are never reverted. An external effect may fire only after its **intent** is durable in the ledger; its outcome is recorded in five states; every irreversible intent is a **barrier** that no fork, revert or rebirth may cross without reconciling it. **Navigator** reports whether a resume point is *consistent with recorded evidence*; safety is enforced at the point of use. When a round ends, a **policy engine** outside the Field decides whether, and which parts of, the final Seal are **sanctioned** into a new Template with lineage. Everything unsanctioned is **purged** on a short clock; the ledger and `ctl` are not.

## 1. The round loop

```
Template(n) ──fork──▶ Vessel ──turns──▶ Seals ──▶ Candidate ──policy──▶ Template(n+1)
     ▲                      │                                               │
     │                      └─ effect ledger (never reverted) ──────────────┤
     └──────────────────────────── lineage ─────────────────────────────────┘
```

Unchanged from v0.3 except that the ledger is drawn outside the revertible path: a Template records the ledger position at sanction, so a Template's ancestry includes which external obligations existed when it was born.

## 2. What Taso knows and refuses to know

### 2.1 Opaque payloads, explicit envelope
Taso parses an envelope on every record and never a payload. New in v0.4: the envelope for `effect` records is **assigned by the Field, not declared by the agent or tool** (§7.1).

### 2.2 Negative space
1. No lock manager.
2. No host-side file handle to Vessel data.
3. No payload parsing.
4. No multi-writer SQLite, no RWX volume, no shared POSIX between Vessels.
5. No automatic trust.
6. No self-sanction.
7. No infinite retention for state; **no purge of the ledger or `ctl`** within audit retention.
8. No zero-RPO promise for state.
9. No in-place base.
10. **No rollback of the effect ledger, ever.** State is reverted; obligations are reconciled.
11. **No dispatch without durable intent.** An effect that fires without an intent record is a Field bug, not a policy question.
12. **No effect authority in a Vessel resumed under `Unknown`.** It may inspect and compute; it may not touch the world until obligations are discharged.
13. **No process-memory recovery.** Vessels restart quiescent from state + transcript (§5.4).

### 2.3 Strong bounds of weak connections
Unchanged. The record schema is the contract; crash-point tests (§12) are the proof.

## 3. Primitives

| Name | Definition | Invariant |
|---|---|---|
| **Template** | Content-addressed manifest + ledger position at birth | Created only by sanction |
| **Vessel** | Sandbox + CoW layers + one Chronicle + one effect authority | One Warden, one Field, one epoch; effect authority is revocable |
| **Field** | The only API across the boundary; **the trusted gateway for effects** | Per-Vessel authenticated; assigns effect class, footprint, outcome |
| **Chronicle** | Single-writer log: state streams + ledger + `ctl` | Accepted prefix anchored at the coordinator by `(lsn, hash)`, not epoch alone |
| **Warden** | Owns the Chronicle; outside the agent's namespace | Durability and audit are one process |
| **Seal** | Cut across **state** streams at a turn boundary; records the ledger position it observed | Verdict: Clean / Unverified / Tainted(kind) |
| **Intent** | Durable ledger record written *before* an effect may dispatch | Carries a stable operation id and canonical footprint |
| **Barrier** | A monotone identifier for an intent whose consequence is irreversible or whose outcome is unknown | A target Seal must account for every barrier through the authoritative head |
| **Lineage** | Fork pointer to a parent Seal + the ledger position at fork | Taint and barriers inherited |
| **Reversion** | Switch state to an earlier Seal | Refused if any unaccounted barrier exists after it |
| **Navigator** | Query over records → `Consistent / Inconsistent(modes) / Insufficient(reasons)` | Proves presence; never infers absence |
| **Candidate / Sanction / Purge** | As v0.3 | Purge never touches ledger or `ctl` |
| **Rebirth** | Replay base + Seal + committed groups of the sealed prefix on any node | Ownership transfer is atomic (§8) |

## 4. Data model (v0.4 deltas)

```
ChronicleHead { lsn: u64, hash: Blake3, epoch: u64 }   // what the coordinator anchors

Ownership {                                            // held by the coordinator, per Chronicle
  epoch: u64,
  holder: WardenId,
  sealed_prefix: ChronicleHead,                        // last head accepted under the previous epoch
  issued_at: Timestamp,
}

Seal {
  id, chronicle, parent, cut: StreamCut,               // state streams only
  layer: LayerRef,
  verdict: Verdict,
  ledger_pos: u64,                                     // highest ledger lsn observed at the cut
  turn: TurnId,
}

Intent {                                               // effect ledger record, written first
  op: OpId,                                            // stable logical identity, survives rebirth
  footprint: Footprint,                                // canonical resource set, Field-assigned
  dispatch: Immediate | Deferrable,
  retry: ProviderDeduplicated { key } | Queryable { probe } | UnsafeToRetry,
  consequence: Irreversible | Compensatable { by: OpId } | NoExternalMutation,
  authority: AuthorityRef,                             // which credential/lease permitted it
  barrier: Option<BarrierId>,                          // set iff consequence != NoExternalMutation
}

Outcome {                                              // effect ledger record, one or more per Intent
  op: OpId,
  state: Prepared | DispatchAuthorized | OutcomeUnknown | ConfirmedApplied | ConfirmedNotApplied,
  evidence: Option<Bytes>,                             // provider receipt, probe result; opaque
}

Group {                                                // state streams only
  gid: GroupId,
  members: Vec<(Stream, lsn)>,
  depends_on: Vec<GroupId>,                            // cross-stream causal order
  commit: bool,                                        // present only in the group's final record
}
```

`Verdict::Tainted(TaintKind)` and `RecordEnvelope` unchanged. The hash chain now includes domain separation, canonical encoding, `ChronicleId` and branch id in the authenticated structure.

## 5. State streams and sealing

### 5.1 Streams
As v0.3, with two additions: every `fs`/`db` record belongs to a `Group`; a Seal cut is valid only at a point where every group it includes is committed and every `depends_on` is satisfied (causal closure). The Warden refuses to cut elsewhere.

### 5.2 Seal
Metadata-only freeze of the upper layer at a causally closed cut. A Seal records `ledger_pos`; that is how barriers are related to Seals.

### 5.3 Cadence
As v0.3: turn boundaries; before long tools; no soft seals by default. The "seal before an irreversible effect" rule is **removed** — it restored execution to the position before the send. Its purpose is now served by intent-before-dispatch (§7.2).

### 5.4 Quiescent-restart contract
Taso captures filesystem state, database pages and the transcript. It does **not** capture process memory, open sockets, timers or queued in-process work. A resumed Vessel starts its agent fresh from the transcript. The harness must be written for this: any in-flight tool call at the time of the cut is either in the ledger (and reconciled) or did not happen. This is stated as a contract rather than inherited silently from DeltaBox, whose DeltaCR process restore Taso does not use.

## 6. Navigator contract (revised)

**Purpose.** Report, from records only, whether resuming from Seal S is *consistent with recorded evidence*. Navigator does not and cannot establish current external validity; that is enforced at use (§7.6).

**Signature.** `navigate(S, head: ChronicleHead, policy: PolicyHash) → Consistent(obligations) | Inconsistent(modes) | Insufficient(reasons)`

**Inputs.** The accepted prefix through `head` (verified against the coordinator's anchor); the full ledger and `ctl`; S's cut, `ledger_pos`, verdict; the policy's required-check inventory (an authenticated input).

**Modes (Inconsistent).**
1. `IncompleteState` — a cut is missing, a record fails the chain, **or a group in the cut is uncommitted or causally open**
2. `StaleDependency` — a verify-result after S reports a dependency S reads has changed; or an `Irreversible`/`Compensatable` intent after S has a footprint overlapping S's read set
3. `Nondeterministic` — non-replayable transcript records after S
4. `UnaccountedBarrier` — a barrier after `S.ledger_pos` not covered by `obligations` (replaces `UnrecordedEffect` and `ExternalDrift`)
5. `AmbiguousOutcome` — an intent after S in `OutcomeUnknown` or `DispatchAuthorized` with no later terminal outcome
6. `InvalidAuthority` — the supplied head is not the coordinator's anchored head, or S belongs to a fenced epoch's unsealed region
7. `AuthorizationDrift` — an authority referenced by an intent after S is recorded revoked/expired in `ctl`

**Reasons (Insufficient).** `MissingVerification(check)`, `MissingOutcome(op)`, `HeadUnanchored`, `UnknownFootprintOverlap`.

**Decision.** `Inconsistent` if any mode is provable. `Insufficient` if any reason holds. `Consistent(obligations)` otherwise, where `obligations` is the list of barriers after S that the caller must discharge (reconcile or suppress) before effect authority is granted. **`Consistent` with a non-empty obligation list is the normal case after any external effect; it is not a failure.**

**Precedence.** `Inconsistent` > `Insufficient` > `Consistent`. A terminal `Unknown`-class effect never upgrades to `Consistent`; it is `Insufficient(MissingOutcome)` until a trusted outcome exists.

**Consumers.**
| Call | Consistent | Insufficient | Inconsistent |
|---|---|---|---|
| fork | proceed; new Vessel inherits obligations; **effect authority withheld until discharged** | proceed in inspect-only mode (no effect authority) | refuse |
| rebirth | proceed; reconcile obligations before granting authority | proceed inspect-only | refuse |
| revert | proceed only after obligations discharged | refuse unless operator override | refuse |

**Operator override.** Binds `(actor, operation, target seal digest, head, policy hash, accepted uncertainty)` into `ctl`. It records risk acceptance; it does not change the verdict.

## 7. The effect ledger

### 7.1 The Field is the gateway
A tool in the Vessel cannot emit an effect record. It makes a call through the Field; the Field's **adapter** (outside the sandbox) assigns `class`, canonical `footprint`, `retry` and `consequence` from its own knowledge of the provider, and only the adapter writes ledger records. A tool that declares anything is ignored. An adapter that does not exist for a provider means the call is refused before dispatch (not "treated as Unknown"); unsupported providers are a policy decision, not a runtime fallback. This closes "malicious tool declares Bufferable" and the Unknown-class denial-of-service path at once.

Egress is mediated: the Vessel has no credentials and no network route except through adapters. Credential isolation is what makes "cannot bypass the buffer" a mechanism rather than an assertion.

### 7.2 Intent before dispatch
Sequence for any effect with `consequence != NoExternalMutation`:
1. Adapter writes `Intent{op, footprint, …, barrier}` to the ledger and fsyncs.
2. Adapter writes `Outcome{op, DispatchAuthorized}`.
3. Adapter dispatches to the provider, using `retry.key` where the provider supports deduplication.
4. Adapter records `ConfirmedApplied` / `ConfirmedNotApplied` with evidence, or `OutcomeUnknown` on timeout or ambiguous response.

A crash at any point leaves an intent whose outcome is at worst `OutcomeUnknown`. **Recovery reconciles every intent in `DispatchAuthorized` or `OutcomeUnknown` before any effect authority is granted**: `Queryable` intents are probed; `ProviderDeduplicated` intents may be safely re-issued; `UnsafeToRetry` intents remain open obligations requiring an operator decision.

### 7.3 Outcome states
`Prepared → DispatchAuthorized → {ConfirmedApplied | ConfirmedNotApplied | OutcomeUnknown}`. `Aborted` exists only as `ConfirmedNotApplied` with evidence that dispatch was prevented. There is no `Failed`. Compensation is a **new intent** linked to the original by `Compensatable.by`; a successful compensation does not erase the original's history and does not clear its barrier — it adds a settled pair the policy may treat as neutral.

### 7.4 Barriers
Every intent with `consequence ∈ {Irreversible, Compensatable}` gets a monotone `BarrierId` (the ledger lsn of the intent). A target Seal S is **eligible** for fork/revert/rebirth only if, for every barrier b with `b > S.ledger_pos` through the authoritative head, b is in the caller's `obligations` and discharged:
- `ConfirmedApplied` + `Irreversible` → obligation is *suppress*: the resumed Vessel is told the operation already happened (the harness receives it as a completed tool result on replay), and the adapter refuses re-dispatch of the same `op`.
- `ConfirmedApplied` + `Compensatable` → obligation is *suppress*, or *compensate* via a new intent if policy says so.
- `OutcomeUnknown` → obligation is *reconcile* (§7.2); until then the Vessel has no effect authority.
- `ConfirmedNotApplied` → no obligation.

Barriers propagate across forks: a sibling branch's barrier on an overlapping footprint is an obligation for this branch too. Footprint equality is conservative — aliases, directory-vs-child and database predicates are handled by the adapter's conflict domain, and unknown overlap is treated as overlap.

### 7.5 Deferrable dispatch (the old "quarantine")
`dispatch = Deferrable` intents are written at call time and dispatched at the next Seal commit. This is a scheduling choice, not a safety property: once dispatched they follow §7.2–7.4 exactly like immediate ones. A dry-run is an optional pre-check and confers nothing.

Admission: per-Vessel quotas on open intents by consequence class, fair scheduling across Vessels sharing an adapter, and refusal (not queueing) when a quota is hit.

### 7.6 Safety at the point of use
Navigator says *consistent*. Safety is established when an effect is dispatched: adapters use immutable versions, conditional writes, leases or provider idempotency keys so the premise verified earlier still holds at use. An adapter that cannot offer any of these is marked `UnsafeToRetry` and its intents are the expensive kind.

## 8. Rebirth and fencing (revised)

1. **Coordinator** holds `Ownership{epoch, holder, sealed_prefix}` per Chronicle. v0: single-node `redb` with fsync under a Warden leader; v1: raft.
2. **Transfer is atomic.** A Warden requesting ownership supplies the head it has verified. The coordinator, in one transaction: reads the current anchored head `H`, sets `sealed_prefix = H`, increments the epoch, records the new holder. Appends under the old epoch are no longer acceptable *by definition of the sealed prefix*, not by epoch comparison.
3. **Accepted head is anchored.** Every successful append advances the coordinator's `(lsn, hash)` for the Chronicle — the object-store head pointer is a cache of this, not the authority. An append is accepted only when the coordinator's CAS from the expected head succeeds under the current epoch. This closes the race where an old Warden's already-authorized CAS lands on the store after transfer: the coordinator refuses it, and even if the object lands, it is outside the sealed prefix and ignored.
4. **Rebirth** follows the sealed prefix exactly: fetch Template, last Seal ≤ prefix, state-stream groups up to the prefix, the **entire** ledger and `ctl` (never truncated). Replay only committed, causally closed groups (§8.5). Reconcile obligations (§7.2, §7.4). Open the Chronicle at the new epoch.
5. **Tail.** State records after the last Seal but within the sealed prefix are replayed only as complete committed groups; a partial group is dropped and the drop is written to `ctl`. Ledger and `ctl` records in the tail are **always kept**. The first Seal after rebirth is `Unverified` with a reason naming the dropped groups, and the policy's required checks must address that reason specifically.
6. **Effect dispatcher fencing.** A Warden that loses ownership must stop its adapters; in-flight provider requests are not cancelled but their outcomes are recorded as `OutcomeUnknown` under the old epoch and reconciled by the new holder.
7. **Partition.** A Warden re-validates ownership at each append (it is the CAS); there is no separate heartbeat to get wrong.

## 9. Sanction policy system
As v0.3, with two inputs added: the Candidate's open obligations (a Candidate with any undischarged barrier is `Never` by hard rule) and the ledger position at sanction (recorded in the Template).

## 10. Threat model (revised cells)

| Claim | Mechanism (v0.4) |
|---|---|
| Tool cannot bypass the ledger | No credentials, no egress except adapters; adapters are the only ledger writers |
| Tool cannot exhaust the ledger | Per-class quotas + fair admission + refusal, not queueing |
| Another Vessel cannot reach the Field | Per-Vessel socket in a per-Vessel namespace; authentication is additional, not the isolation |
| Verifier cannot attest its own ancestry | Verifier key issued by Warden at fork; signing key never enters the Vessel; check code comes from the verifier Template, not the Candidate |
| Warden cannot delete audit retention | Ledger and `ctl` segments written to a bucket with a retention lock the Warden's credential cannot lift |
| Network cannot forge | Authenticated transport; the hash chain is integrity, not authentication |
| Storage cannot replace the chain undetected | Coordinator anchors `(lsn, hash)`; a self-consistent replacement chain fails the anchor |

Non-goals unchanged (compromised Warden, compromised coordinator, runtime side channels). The anchor at the coordinator is the one step taken toward the compromised-Warden case because it is nearly free; it does not claim to cover it.

## 11. Retention
State: short, purged. Ledger + `ctl` + Seal metadata + lineage: long, retention-locked. Invariant: every barrier ever created is reconstructible for the audit period.

## 12. Prototype plan (revised)

**P0 — invariants and crash points.** Before any performance work. Encode as property tests over an in-memory model of Chronicle + coordinator + two Wardens + one adapter + a fake provider:
- *Accepted prefix:* no record outside the sealed prefix is ever replayed; both reviewer interleavings (old-Warden CAS after transfer; two Wardens believing ownership) are test cases.
- *Checkpoint completeness:* a Seal never includes an uncommitted or causally open group.
- *Dispatch authorization:* no provider call without a prior fsynced intent (the fake provider asserts it).
- *Outcome evidence:* a crash injected at every point in §7.2 leaves a reconcilable ledger; the reviewer's mail-duplication trace and payment-timeout trace are test cases; expected result is zero duplicate provider effects across 10k randomized crash schedules.
- *Branch authority:* a fork from a pre-barrier Seal cannot dispatch until obligations are discharged; sibling-branch barriers on overlapping footprints are detected.
- *Navigator soundness:* a labeled corpus of Chronicles (including the reviewer's traces) where `Consistent` with empty obligations is never returned when a duplicate effect is possible.

**P1 — WAL shipper.** As v0.3, plus group/commit markers in `db` records.
**P2 — Rebirth.** As v0.3 criteria, plus: the sealed-prefix transfer is used, dropped partial groups are reported, ledger tail is intact.
**P3 — Seal + Crab measurement.** Unchanged.
**P4 — Navigator + attacks.** The three *Safe to Resume?* attacks plus the reviewer's traces (#1, #2, #3, #4, #7, #8); expected: all refused or reconciled, zero duplicate effects.
**P5 — Sanction loop.** Unchanged, plus a Candidate with an open obligation is `Never`.

## 13. Crates
`taso-core` gains `ledger` (intent, outcome, barrier, obligations — pure) and `group`. `taso-field` gains `adapter` (the gateway trait and a fake provider for tests). `taso-warden` gains the coordinator with the atomic transfer. Still three crates.

## 14. Open problems
- Footprint canonicalization across adapters (the conflict-domain problem) — start conservative, measure false-overlap rate.
- `UnsafeToRetry` intents left open after a crash need an operator workflow; this is the one place a human is in the recovery path by design.
- Verifier isolation: how check code is sourced from a verifier Template without the Candidate influencing it.
- Coordinator v1 (raft) and retention-locked buckets on Garage — confirm both exist or plan substitutes.
- Whether a quiescent restart is acceptable for every harness; Hermes needs checking.
